# MetaCompass — Project Rules for Claude Code

Agent answering ownership, lineage and change-impact questions over synthetic
BI metadata. Independent portfolio project.

- Full specification: docs/plan/13_METACOMPASS_MASTER.md (read the relevant § before each task)
- Where we are: PROGRESS.md (read first, update after every task)

## Absolute rules (spec §13.1)
1. All data is synthetic. Fictional company: Northwind Motors. No real company code, data, schema, config, questions or internal names.
2. Never claim this project is a rewrite of work done at any company.
3. Never fabricate results. results.md is generated by eval/report.py only. Unrun cells stay placeholders.
4. Never weaken, skip or delete a test to make it pass. If a test seems wrong, write it under "Açık sorular" and ask.
5. Never tune prompts or thresholds on test-set results.
6. No secrets in the repo. Only .env (ignored) and .env.example (empty values).
7. data/, docs/plan/, docs/learn/ are never committed.
8. No push, deploy, paid test-set/ablation run or budget overrun without explicit approval.
9. Do not expand scope (spec §2). If asked, remind and ask for the reason.
10. Every module starts with a short purpose docstring; non-obvious code has "why" comments.

## Work loop (spec §13.2)
read PROGRESS → find spec § → write approach → test first → implement → green →
python scripts/check_all.py → update PROGRESS → local commit (Conventional Commits) → next.
Stop and ask in the situations listed in spec §13.3.

## Style
- Talk to me in Turkish. Code, identifiers, commits, README in English.
- Explicit, readable code over clever abstractions. I must be able to defend every line.
- When you make a design choice not in the spec, state the alternative and trade-off.
- If you think I am wrong, say so directly. No flattery.
- When a phase introduces a new concept, write docs/learn/NN_<topic>.md (spec §13.7).
